# Dev log — 2026-08-07: G-03 (HA) re-scoped, not implemented

## What happened

Picked up gap G-03 (no Proxmox HA configured) as the next infrastructure
item, following the gap register's own priority order. Before designing
anything, re-read the master plan's exact text (§3, §8, §10) instead of
working from the register's paraphrased citation, per this project's
working discipline.

## What was found

The register cited "§8 recovery language; implicit in 'restore into a
healthy site'" as the reason G-03 was High severity. The plan's actual text
says something different and more specific:

- §3 Standard tier promise is backup/restore ("daily encrypted off-site
  backup... restore into a healthy site"), not live failover.
- §3 explicitly rules out "active-active promise."
- §10 explicitly states: "Advanced automatic failover comes later" — i.e.
  out of MVP scope by the plan's own words.

So G-03 as scored didn't reflect what the plan actually requires. Building
Proxmox HA now would have been scope-ahead-of-evidence work with no plan
requirement pulling it forward.

## What changed

- `docs/decisions/2026-08-07-g03-ha-deferred.md` — new decision record
  documenting the finding and the decision to defer.
- `docs/phase-0/gap-register.md` — G-03 severity revised High → Low,
  citation corrected, "Immediate next actions" updated to drop HA from the
  priority path.

## What did not change

No live infrastructure was touched. `cluster/ha/resources` on Guild-A is
still `[]`, deliberately, until the plan's own "later" is actually reached
(realistically alongside Warm Standby / Protected tier work).

## Still open

Per the register's own updated priority order, G-14 (policy for
pre-existing non-GuildCloud workloads sharing cluster capacity) is next.
