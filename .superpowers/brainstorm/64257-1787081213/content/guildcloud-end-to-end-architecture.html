2. Placement authority

New component

Health snapshots

Each worker publishes cluster, node, storage, template, network, backup, monitoring, and heartbeat state.

Eligibility filter

Online, fresh heartbeat, tested image, admitted node, enough CPU/RAM/disk, and 30% reserve retained.

Atomic reservation

One database transaction chooses cluster_id + node, inserts the capacity hold, and prevents double placement.

Best-fit score

Prefer the eligible node with strongest post-placement headroom; deterministic tie-break avoids unstable decisions.

↓ operation is locked to exactly one worker
